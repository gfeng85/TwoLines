# 双线大战

一款纯前端（单文件 HTML + Canvas）的双人光轨对战小游戏。

**快速开始**：用浏览器打开 `index.html` 即可游玩，无需安装依赖、无需构建。

> 本文档基于 `index.html` 当前实现编写，描述游戏的玩法规则、操作方式与底层实现逻辑（含 0.5 秒挽救机制）。

---

## 一、游戏概述

双线大战是一款固定竞技场的双人光轨对战小游戏：

- 两名玩家各控制一条光轨，从屏幕**横向中位线**的 1/4 与 3/4 等分处出发，**相向而行**。
- 光轨随行驶不断延长，撞到墙壁、己方光轨或对方光轨即输掉本局。
- 局 → 盘 → 场三级计分：**先得 11 局者赢下一盘，整场三盘两胜**。
- 支持**双人对战**（同键盘）与**人机对战**两种模式。

---

## 二、操作方式

| 场景 | 蓝方（玩家 1） | 红方（玩家 2 / 电脑） |
|---|---|---|
| 双人对战 | `W` `A` `S` `D` | 方向键 `↑` `↓` `←` `→` |
| 人机对战 | `WASD` **或** 方向键均可 | 由 AI 自动控制 |

- **暂停 / 继续**：按 `P` 或 `Esc`，也可点击画面右上角「暂停」按钮。
- **切后台自动暂停**：浏览器标签页隐藏时自动暂停，返回后手动继续。
- **触屏设备**：画面左下 / 右下角自动出现两套虚拟方向键（仅 `pointer: coarse` 设备显示；人机模式下仅显示蓝方一套）。
- 方向键无法使光轨**原地掉头 180°**（防止直接撞回自身轨迹）。

## 三、竞技场与坐标系

| 参数 | 值 | 说明 |
|---|---|---|
| `COLS` | 120 | 网格列数 |
| `ROWS` | 75 | 网格行数 |
| `CELL` | 8 px | 单格边长 |
| 画布逻辑尺寸 | 960 × 600 px | 固定竞技场（8:5） |
| `UP/RIGHT/DOWN/LEFT` | 0 / 1 / 2 / 3 | 方向枚举 |
| 方向向量 | `DX=[0,1,0,-1]` `DY=[-1,0,1,0]` | 上右下左 |

- 网格用 `Uint8Array(COLS*ROWS)` 表示占用：`0` 空、`1` 蓝方、`2` 红方。
- 出生点：`midY = floor(75/2) = 37` 行（即中位线所在行）。
  - 蓝方出生在 `(30, 37)`，初始方向 **右**；
  - 红方出生在 `(90, 37)`，初始方向 **左**；
  - 两轨出发后在中线相遇，形成正面交锋。
- 画面正中绘制一条虚线标识中位线，作为出生基准。

## 四、运动系统

- **固定时间步**：`TICK = 45ms`，约 22.2 格/秒；主循环用 `requestAnimationFrame` + 累加器（`acc`）保证步进稳定，不使用 `setInterval`。
- **输入队列**：每次按键把 `{dir, t}`（方向 + 按下时刻 `performance.now()`）压入队列，**最多保留 3 个**；无效方向（180° 掉头、与当前同向）直接忽略。
- **每 tick 应用输入**：从队列头部弹出最早输入，若已超过 0.5 秒视为过期丢弃；若与当前方向相反/相同也丢弃；应用第一个有效输入后再计算前进目标格。
- **移动**：目标格安全则光轨头前移一格，并在离屏画布上补画一段轨迹。

---

## 五、挽救机制（核心 · 对玩家无感）

撞到物体不再立即判死，而是提供 **0.5 秒** 的挽救窗口，全程无任何闪烁、倒计时或提示 UI，目的在于让玩家可以**贴墙 / 贴线行驶**，提升操控性。

机制分两层：

### 5.1 撞前缓冲（无缝转向）

每个按键输入带时间戳，**0.5 秒内有效**。当光轨下一步将撞上障碍物时：

1. 按时间从新到旧查找队列中 0.5 秒内的输入；
2. 找到某个方向：非 180° 掉头、且目标格安全（界内且未被占用）；
3. 命中则**立即转向并在同一 tick 移动**——玩家视角下就是贴着障碍物滑过去，完全无感、无停顿。

典型场景：玩家在墙角快速连按「上→左」，上方是墙、左侧通畅，则撞上前一刻自动采用「左」向无缝转弯。

### 5.2 撞后静默挽救期

若撞上瞬间没有可用缓冲输入，光轨头**静默冻结**（无任何提示），进入最长 **0.5 秒** 的挽救期：

- 期间按向**无阻挡**的方向键 → 立即转向，恢复行驶；
- 按向仍有阻挡的方向 → 不解除挽救，计时继续；
- 0.5 秒内始终没有有效输入 → 判输掉本局。

### 5.3 相关判定细节

| 情况 | 结果 |
|---|---|
| 一方撞墙 / 撞线且无挽救 | 对方赢得本局 |
| 双方同时撞上（含对撞同一格） | 双方进入挽救期，先转向者存活 |
| 双方挽救期均超时 | 判**平局**，本局不计分，重新开局 |
| 一局累计步数超过 `MAX_STEPS=25000` | 判平局（防止极端僵局） |

> 语义说明：碰撞判定基于**移动前**的网格快照（含双方当前头部），因此「对方刚离开的格子」在当 tick 内仍视为被占用，属保守判定。

## 六、每 tick 判定流程（step 伪代码）

```
每 tick：
  1. 步数 +1，超过 MAX_STEPS → 平局
  2. 对每个玩家（挽救中者跳过）：
       从队列弹出最早有效输入（0.5s 内、非掉头）并应用
       计算当前方向的目标格
       安全 → 状态 1（可移动）；阻挡 → 状态 0
  3. 状态 0 的玩家尝试「撞前缓冲」tryRescue：
       命中 → 转向并置为状态 1（本 tick 移动）
       未命中 → 进入静默挽救期（状态 -1）
  4. 若双方状态均为 1 且目标格相同（对撞）→ 双方进入挽救期
  5. 状态 1 的玩家执行移动（更新占用、补画轨迹）
```

每帧额外执行 `resolveDanger(now)`：检查挽救中玩家是否超时（`now - dangerT >= 500ms`），超时即按上述规则判负 / 判平局。

## 七、计分与胜负结构

- **局（Round）**：一局内率先无法移动者输；胜者 `roundScore + 1`。
- **盘（Set）**：`roundScore` 先达到 **11** 者赢下一盘：`setScore + 1`，局分归零进入下一盘。
- **场（Match）**：`setScore` 先达到 **2** 者赢得整场比赛（三盘两胜）。
- 所有分数在 HUD 顶部实时显示：局分、盘分、当前盘号。

---

## 八、人机对战（AI 设计）

AI 每 tick 决策一次，评估三个可行方向（排除 180° 掉头）：

```
score = 洪水填充可达格数(上限 8000)      // 主要依据：活路越多越安全
      + 12（保持当前方向的直行偏好）      // 减少无谓拐弯
      + max(0, (50 - 与对手曼哈顿距离) * 1.5)  // 靠近对手施压
```

- 选择得分最高的方向，通过同一套 `setDirection` 输入通道驱动，因此 AI 同样受 0.5 秒挽救机制约束（AI 的洪水填充只会选择安全方向，通常不会触发挽救）。
- 洪水填充把双方已有轨迹视为墙，只统计可达空格数。

## 九、渲染方案

- **三层渲染**：
  1. **静态层**（离屏画布）：深色背景、16px 间隔淡网格、中位线虚线、边框——每局开局绘制一次；
  2. **轨迹层**（同一离屏画布）：随移动增量补画每段轨迹（双层描边：宽半透明光晕 + 细实芯，制造霓虹光轨效果）；
  3. **动态层**（主画布）：每帧 `drawImage` 整体拷贝离屏画布，再绘制光轨头（呼吸脉动圆点）与开局倒计时。
- **高分屏适配**：画布物理分辨率按 `devicePixelRatio` 放大（上限 2），逻辑坐标不变。
- 轨迹只画一次（增量绘制），避免每帧重描数千个点，保证性能。

## 十、状态机与主循环

游戏阶段 `S.phase`：

```
menu ──选择模式──▶ countdown(3·2·1) ──▶ playing
playing ──撞线/超时──▶ roundEnd / draw(平局)
playing ──局分达 11──▶ setEnd ──▶ 下一盘 countdown
setEnd ──盘分达 2──▶ matchEnd（再来一局 / 返回菜单）
playing / countdown ──P/Esc/切后台──▶ paused ──▶ 恢复
```

- 主循环仅在 `countdown` / `playing` 阶段运行；暂停时 `cancelAnimationFrame` 真停循环，挽救计时同步冻结。
- 开局倒计时 `COUNTDOWN=2100ms`，每 700ms 一个数字（3、2、1），Canvas 中央大号字体显示。
- 每帧 `dt` 上限截断为 100ms，避免切后台恢复瞬间的步进跳变。

## 十二、已知边界

- 挽救期冻结是唯一可见的机械停顿（无任何警示 UI），超时前按下有效方向键即可继续。
- 「走入对方刚离开的格子」在当 tick 内被判阻挡（移动前网格判定），属保守且公平的语义。
- 双方同时进入挽救期且都未转向时判平局，局分不增减。
- 暂停会同时冻结挽救计时；切后台自动暂停，避免玩家在不可见时被淘汰。
